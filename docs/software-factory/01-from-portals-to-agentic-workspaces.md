# 01. From Legacy Portals to Agentic Workspaces

> **Track 1 Guide**: How the `@cmp` monorepo replaced static Backstage YAML catalogs and manual scorecards with live workspace contracts, `AGENTS.md` constitutions, and clean polyglot isolation.

---

## 1. Core Concepts

### Why We Sunset Backstage & Manual Scorecards

Earlier in the monorepo's lifecycle, `apps/backstage/` hosted an independent Yarn 4 developer portal backed by `catalog-info.yaml` descriptors spread across `apps/`, `packages/`, `infra/`, and `docs/`, alongside `packages/exp-quality-scorecard/`. While useful for multi-team service discovery in large enterprises, that model caused three forms of drag in an agentic monorepo:

1. **Dual-Maintenance Drift**: Every new package or experiment required hand-authoring `catalog-info.yaml` metadata that had no runtime effect on builds, tests, or typechecks.
2. **Toolchain Friction**: Backstage required Yarn 4 hoisting rules incompatible with `pnpm`'s strict `node_modules` isolation, plus root `devDependencies` (`@backstage/cli`, `@techdocs/cli`) that slowed installs without validating product code.
3. **Passive Governance**: Manual scorecards described quality expectations on paper instead of enforcing them automatically in the developer/agent edit loop.

### Live Machine-Enforceable Contracts

Instead of passive catalog files, the monorepo uses **live build and governance files** that tools and agents read directly:

- **`pnpm-workspace.yaml`**: Defines the exact boundary of Node/TypeScript workspace packages managed by `pnpm`.
- **Root `package.json` + `turbo.json`**: Exposes standardized workspace pipelines (`build`, `typecheck`, `lint`, `test`, `clean`) and Agentic Software Factory commands (`gen:app`, `gen:slice`, `verify:slice`).
- **Per-App `AGENTS.md` Constitutions**: Concise, repo-local rules inside each app (`apps/web/AGENTS.md`, `apps/pulse/AGENTS.md`, and every app generated by `pnpm gen:app`) specifying Pure Functional Core (`ADR-007`), WCAG 2.2 AA contrast gates, Zero-PII telemetry rules, and verification commands.
- **Automated Guardrail Audit**: `pnpm verify:slice` scans `apps/*` to confirm `AGENTS.md` and `README.md` exist and fails immediately if any legacy `catalog-info.yaml` reappears.

### Polyglot Workspace Isolation (`apps/pulse` vs. `pnpm` Packages)

Not every application in a multi-stack monorepo uses `pnpm`:

- **`pnpm`-Managed Workspaces**: `apps/web` (`@cmp/web`), any generated `apps/<name>` (`@cmp/<name>`), `packages/config` (`@cmp/config`), `packages/utils` (`@cmp/utils`), and `packages/factory` (`@cmp/factory`).
- **Polyglot Reference Architecture (`apps/pulse`)**: `apps/pulse` is a Kotlin Multiplatform / Android (Gradle), Spring Boot 4 / Java 21 (Gradle), and Angular 21 (`npm` with its own `package-lock.json`) reference app. Excluding `apps/pulse` from `pnpm-workspace.yaml` prevents `pnpm` from attempting to link or hoist `apps/pulse/web`'s `npm` tree while keeping `apps/pulse` in the same repository for shared docs, ADRs, and architectural auditing.

## 2. How It Functions (Real Code Walkthrough)

### `pnpm-workspace.yaml` Boundaries

In `/pnpm-workspace.yaml`, all immediate subdirectories under `apps/` and `packages/` are included *except* `apps/pulse`:

```yaml
packages:
  - 'apps/*'
  - '!apps/pulse'
  - '!apps/pulse/**'
  - 'packages/*'
```

This guarantees:
- `pnpm install` links `@cmp/utils` and `@cmp/config` into `@cmp/factory`, `@cmp/web`, and newly generated `apps/*` via `workspace:*`.
- `pnpm -r` and Turborepo never collide with `apps/pulse`'s Gradle wrappers or `apps/pulse/web/package-lock.json`.

### Root `package.json` & `turbo.json` Orchestration

In root `/package.json`, Backstage CLI dependencies are gone and the factory CLI is exposed directly as root scripts:

```json
{
  "scripts": {
    "build": "turbo build",
    "dev": "turbo dev",
    "lint": "turbo lint",
    "test": "turbo test",
    "typecheck": "turbo typecheck",
    "clean": "turbo clean && rimraf node_modules",
    "gen:app": "node packages/factory/dist/src/cli.js gen:app",
    "gen:slice": "node packages/factory/dist/src/cli.js gen:slice",
    "verify:slice": "node packages/factory/dist/src/cli.js verify"
  },
  "devDependencies": {
    "rimraf": "^6.0.0",
    "turbo": "^2.8.17"
  }
}
```

Meanwhile, `/turbo.json` encodes the build dependency DAG:
- `build` and `typecheck` specify `"dependsOn": ["^build"]`, ensuring `@cmp/utils` builds before downstream consumers (`@cmp/factory`, `@cmp/web`, generated apps) compile.
- `test` and `lint` cache cleanly while excluding `**/*.md` inputs so documentation updates do not invalidate TypeScript build caches.

### How Agents Consume `AGENTS.md` + Stack Best Practices

When an engineer or AI agent opens an app:
1. It reads the app's `AGENTS.md` (for example, [`apps/web/AGENTS.md`](../../apps/web/AGENTS.md) or [`apps/pulse/AGENTS.md`](../../apps/pulse/AGENTS.md)) to learn the exact architectural invariants and required verification commands.
2. It consults [`docs/stack-best-practices/`](../stack-best-practices/README.md) and [`docs/software-factory/`](./README.md) for stack-specific implementation patterns.
3. After editing, it runs `pnpm verify:slice` (or `pnpm verify:slice --json`) to confirm all structural, accessibility, privacy, typecheck, and test gates pass.

## 3. How to Implement

### Adding a New Workspace App (Recommended Factory Path)

1. Ensure `@cmp/factory` is built (`pnpm build` if freshly cloned).
2. Scaffold the app using the factory CLI:
   ```bash
   pnpm gen:app my-product --stack=web-ts
   ```
3. Link workspace dependencies and verify:
   ```bash
   pnpm install --no-frozen-lockfile
   pnpm verify:slice --target=@cmp/my-product
   ```

### Authoring an `AGENTS.md` Constitution for a Non-Generated or Polyglot App

If you bring a polyglot app into `apps/<name>/` (like `apps/pulse/`):
1. Exclude it in `pnpm-workspace.yaml` (`- '!apps/<name>'` and `- '!apps/<name>/**'`) if it uses Gradle, Cargo, Maven, or standalone `npm`.
2. Create `apps/<name>/AGENTS.md` covering five concise sections:
   - **Pure Functional Core (`ADR-007`)**: Keep domain logic stateless and framework-free.
   - **WCAG 2.2 Level AA Gate**: Require automated contrast verification (`>= 4.5:1` normal text, `>= 3.0:1` large text/UI).
   - **Zero-PII Telemetry**: Require token/email scrubbing before any breadcrumb or crash report is emitted.
   - **Desktop/Responsive UX (`ADR-009`)**: Reference `docs/stack-best-practices/` layout and ergonomics standards.
   - **Verification Gate**: List the exact commands that prove the app builds and passes tests.
3. Add `apps/<name>/README.md` with quickstart and architecture notes so `pnpm verify:slice` passes the `Guardrail & AGENTS.md Audit`.

### Checklist: Maintaining Zero Catalog Bloat

- [ ] Never add `catalog-info.yaml` files anywhere in the repository (`pnpm verify:slice` explicitly fails if any exist).
- [ ] Keep `apps/` and `packages/` registered cleanly in `pnpm-workspace.yaml` (excluding only genuinely non-pnpm polyglot directories like `apps/pulse`).
- [ ] Expose standard `build`, `test`, `lint`, `typecheck`, and `clean` scripts in every workspace `package.json`.
- [ ] Update `docs/software-factory/`, `docs/stack-best-practices/`, or `mkdocs.yml` in the same commit when introducing a new stack or workspace convention.
